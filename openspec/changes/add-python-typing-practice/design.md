# Design

## Context

当前目录只有 OpenSpec 配置、技能及 IDE 元数据，没有可复用的业务代码、依赖清单或测试。动机见 `proposal.md`；行为契约分别见 `specs/typing-practice/spec.md`、`specs/keyboard-lessons/spec.md` 和 `specs/practice-records/spec.md`。

已确认的技术栈为 Flask、SQLite 和原生 HTML/CSS/JavaScript。用户通过本机浏览器使用，主要输入设备是标准 QWERTY 实体键盘。以下接口、课程细分和交互细节是本提案拟定的实施方案，供实施前审阅。

## Goals / Non-Goals

**Goals:**

- 让输入反馈在浏览器内即时完成，Python 负责内容、结果校验和持久化。
- 三种模式共用输入与计分机制，客户端预览和服务端结算使用相同定义。
- 用稳定课程标识和持久成绩恢复进度，避免两个独立状态源发生分歧。
- 保持代码容易理解：一个应用、一份本地数据库、无前端构建步骤。

**Non-Goals:**

- 不检测实际使用的手指，不接入摄像头或操作系统级键盘监听。
- 不保存可继续恢复的半途练习；关闭页面后从已保存的课程进度重新开始。
- 不提供在线竞技防作弊、跨设备同步、账号系统或数据库管理后台。

## Decisions

### 1. Flask 单体与清楚的职责边界

采用 Flask 应用工厂，集中注册页面、JSON 接口及数据库生命周期。浏览器通过同源请求获取内容和提交成绩，逐次输入无需往返服务器。Flask 的路由把请求交给对应 Python 函数，模板生成 HTML，静态文件负责样式与交互，见 [Flask Quickstart](https://flask.palletsprojects.com/en/stable/quickstart/)。

建议结构：

| 路径 | 职责 |
|---|---|
| `typing_app/__init__.py` | 创建应用、加载配置、注册页面与接口 |
| `typing_app/routes.py` | 页面及 JSON 请求处理，调用业务逻辑 |
| `typing_app/db.py` | 按请求获取数据库连接，初始化及关闭连接 |
| `typing_app/scoring.py` | 成绩校验、速度计算和准确率判定 |
| `typing_app/courses.py` | 课程读取、已学字母集合和解锁查询 |
| `typing_app/templates/` | 公共布局、首页、练习页、课程页、历史页 |
| `typing_app/static/` | CSS、输入状态机、计分与虚拟键盘 JavaScript |
| `typing_app/data/` | UTF-8 内置文章和课程数据 |
| `instance/typing.sqlite3` | 本机持久化数据，排除出版本控制 |
| `tests/` | 后端回归验证及前端验收样例 |
| `requirements.txt`、`README.md` | Flask 依赖和 Windows 启动、数据位置说明 |

直接运行依赖为 Flask；使用 Python 自带的 `sqlite3` 和标准库测试工具。暂不加入 ORM、前端框架、CSS 框架或 Node 构建流程。Django 的数据模型、认证和后台是一种可选架构，但本项目已经选择 Flask；原生前端能够承担当前规模的交互。

### 2. 练习会话和输入状态机

开始练习前向后端创建一次 `run`，保存模式、语言、目标文本快照和限时时长；课程会话还保存关卡标识。后端此时校验关卡是否已开放。创建会话不等于保存完成成绩，只有结算后才进入历史列表。

前端状态分为 `ready`、`running`、`finished`、`saving`、`saved`、`save-failed`。首次已提交字符或首次 `compositionstart` 触发开始计时；选素材和等待不计时。重试创建新的会话标识，清空本次状态，不复用上次成绩标识。

- 全文和关卡：已提交作答长度达到目标长度时自动结束，错误字符也占一个目标位置。结束前允许退格、删除和替换，结束后保留结果供重试或保存。
- 限时：选择 60、180 或 300 秒；到截止时刻冻结成绩。目标文本按原字符序列循环，不额外插入计分字符，跨轮累计作答与正确数。
- 作答区阻止粘贴、拖入和浏览器自动更正；自定义素材区正常允许粘贴。输入法组字不被当作批量粘贴。
- 未开始或中途放弃的会话不生成成绩；字符尝试数为零时也不保存有效成绩。
- 结算只触发一次；重试保存沿用冻结的同一份结果，重复点击不生成新的会话。

时间使用 `performance.now()` 的差值计算，定时器只刷新显示，不通过逐秒减一累计时间。每次输入处理前重新检查截止时间，后台标签页恢复时也按实际截止时刻结算；浏览器定时器延迟不增加可用练习时间。[MDN 的时间说明](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now)解释了该时钟相对于系统时间调整的区别。

### 3. 中文组字与字符增量

使用真实的文本输入控件，区分 `compositionstart` 至 `compositionend` 的组字阶段和已提交文本。组字期间只展示临时内容，不更新正确、错误或字符尝试计数；组字完成后统一处理提交的文字，随后携带相同提交的输入事件不得再次记分。取消组字不产生字符尝试。[compositionend](https://developer.mozilla.org/en-US/docs/Web/API/Element/compositionend_event)可能表示组字完成或取消，不能仅凭事件发生就认为新增了文字。

维护最后一次已提交文本与编辑范围，插入和替换产生新的字符尝试，删除只改变当前作答。组合事件标志为主，`isComposing` 为补充，避免只依赖某一输入事件属性。限时到达时使用最后的已提交快照，丢弃尚未确认的组字内容；截止之后的提交不计分。

初版以 Unicode 码点作为字符单位，JavaScript 与 Python 使用一致的字符序列；统一将 CRLF 转为 LF，保留空格、标点及其他正文内容，不对用户输入作隐式大小写转换。中文文章模式只根据上屏文字判定，不把拼音按键映射为关卡指法。字母关卡要求英文输入，输入法或大小写状态不合适时提供可理解的提示。

### 4. 计分口径和后端结算

维护两个不同的量：历史字符尝试和当前最终作答。退格不会抹去历史错误，但当前作答中的正确字符数随纠正而变化。

| 指标 | 定义 |
|---|---|
| `attempted_chars` | 所有已提交插入或替换字符的累计数量 |
| `correct_attempts` | 字符提交时与对应目标位置一致的累计数量 |
| `error_attempts` | `attempted_chars - correct_attempts` |
| `final_correct_chars` | 最终作答中与目标对应位置相同的字符数；限时模式按目标循环比较 |
| 准确率 | `correct_attempts / attempted_chars * 100`，无尝试时为 0 |
| 中文速度 | `final_correct_chars / (elapsed_ms / 60000)`，字符/分钟 |
| 英文及关卡速度 | `final_correct_chars / 5 / (elapsed_ms / 60000)`，WPM |
| 关卡通过 | 目标已全部作答，且 `correct_attempts * 100 >= attempted_chars * 95` |

速度计算中有效用时至少取 1 毫秒以避免除零，显示值保留合理小数位；通关使用原始计数比较，不使用显示后的百分比。全文和关卡允许带错误结束，因此最终文本不必全对，准确率也不会因为已纠正错误而自动变为 100%。

浏览器提交最终作答、累计尝试数、正确尝试数和用时；后端根据保存的目标快照重算最终正确字符数、准确率、速度、完成条件和通过状态，不接收客户端直接指定的解锁状态。校验非负有限数值、正确尝试数不大于总尝试数、作答长度不大于累计尝试数，以及模式与时长合法等一致性条件。限时练习的结算用时采用所选时长；全文和关卡使用实际用时。

本机自用场景信任浏览器报告的历史尝试计数；只上传汇总和最终作答，不保存逐次按键日志。该校验防止常见错误请求和前后端状态分歧，不作为在线竞赛的防作弊机制。

### 5. 课程数据及标准指法

课程存为版本化的本地数据，关卡使用稳定标识，不依赖页面下标作为永久身份。拟定的 16 关如下；每个字母引入关卡包含新键练习和已学键复习。

| 顺序 | 新字母或训练主题 |
|---|---|
| 1 | F、J：左右食指定位 |
| 2 | D、K：中指 |
| 3 | S、L：无名指 |
| 4 | A：左手小指，并说明右手小指的基准位置在分号键 |
| 5 | G、H：基准行食指扩展 |
| 6 | R、U：上排食指 |
| 7 | E、I：上排中指 |
| 8 | W、O：上排无名指 |
| 9 | Q、P：上排小指 |
| 10 | T、Y：上排食指扩展 |
| 11 | V、M：下排食指 |
| 12 | C、X：下排左手中指及无名指 |
| 13 | Z：下排左手小指 |
| 14 | B、N：下排食指扩展 |
| 15 | 全部 26 字母混合复习 |
| 16 | 使用已学字母的常见英文单词 |

以 F/J 和基准位置起步，再扩展键盘范围，参考 [TypingClub 教师手册](https://typingclub.typingclub.com/m/edclubdocs/media/pdf/typing-jungle-handbook.pdf)的基准行、上排、下排教学思路；具体 16 关划分是本项目的设计建议。首版训练小写字母和空格，键帽显示大写只是标识；数字、标点专项和 Shift 专项不纳入这套基础通关课程。

每关记录 `id`、顺序、名称、新字母、已学字母集合、练习文本、教学提示及课程版本。练习文本为固定、可检查的原创字符组合和单词，每关均有足够字符形成有效练习；自动检查新字母数、全字母覆盖和未学字母泄漏。空格提示拇指。

指法映射集中保存：左手小指 Q/A/Z，无名指 W/S/X，中指 E/D/C，食指 R/F/V/T/G/B；右手食指 Y/H/N/U/J/M，中指 I/K，无名指 O/L，小指 P。虚拟键盘同时区分目标键、实际按键和基准键，并通过文字给出手指名称；不推断真实手指。

### 6. 页面与反馈组织

页面以练习工作区为中心，使用中文标签和本地系统字体，全部样式及脚本随应用提供。界面检索未得到匹配的打字工作区模板，因此采用通用可访问性原则，而不套用营销页或儿童化视觉主题。

- 首页：三个模式入口，文章模式中选择语言、来源与时长。
- 练习页：上方显示模式和统计，中间为目标文本与作答区；关卡模式下方显示键盘和手指提示。结算区提供成绩、保存状态和重试。
- 课程页：按教学阶段展示关卡，用文字和图形区分已通过、可练习及锁定，优先呈现下一待练关卡；已开放关卡可复习。
- 历史页：按时间倒序显示模式、语言、素材、速度单位、准确率、用时和通过状态，提供空状态。

正确、错误、当前目标不只用颜色区分；提供可见焦点、输入控件标签与“继续输入”操作，导航不劫持练习按键。正文保持可读字号和足够对比度，界面在较窄窗口内仍可操作，虚拟键盘保留行列关系。动态结果和保存状态使用低频辅助提示，不对每次按键朗读。无需外部字体、图片或 CDN，启动完成后练习不依赖互联网。

### 7. API 契约

页面与接口同源，语言使用 `zh`、`en`，模式使用 `full`、`timed`、`lesson`，时间采用毫秒或明确命名的秒字段，避免混用。下面的路径是本提案拟定的接口。

| 方法与路径 | 行为 |
|---|---|
| `GET /`、`GET /practice` | 首页与共享练习页面 |
| `GET /lessons`、`GET /history` | 课程和历史页面 |
| `GET /api/articles?language=zh` | 获取对应语言的内置素材 |
| `GET /api/lessons` | 课程、通过状态、解锁状态和下一待练关卡 |
| `POST /api/runs` | 接收模式、语言、素材标识或自定义文本、限时时长或关卡标识；校验后生成稳定会话标识并返回目标 |
| `POST /api/runs/<run_id>/result` | 接收冻结的最终作答、尝试计数和用时，计算并保存一次成绩 |
| `GET /api/history?limit=20&offset=0` | 分页返回按完成时间倒序排列的历史成绩 |

请求和响应使用 JSON，参数命名统一为 snake_case。新成绩保存返回 201，相同结果重试返回 200；格式或计数错误为 400，关卡未解锁为 403，未知标识为 404，同会话提交不同结果为 409，临时数据库写入失败为 503。响应带简短可展示的错误信息。输入素材始终使用模板转义或 `textContent` 展示。

### 8. SQLite 持久化及幂等保存

SQLite 把表和索引保存在本地文件，由进程内库读写，不必额外运行数据库服务。数据库连接按请求获取并在请求结束关闭，见 [Flask 的 SQLite 教程](https://flask.palletsprojects.com/en/stable/tutorial/database/)。相比浏览器本地存储，数据库在清理浏览器缓存后仍可保留，也方便 Python 统一校验和查询历史；相比独立数据库服务，更符合本地单人使用方式。

初版使用两张主表：

- `practice_runs`：会话标识、模式、语言、素材类型及标识、显示标题、目标文本快照、课程版本、限时时长和创建时间。
- `practice_results`：以会话标识为唯一键，保存原始尝试计数、最终正确数、最终长度、用时、计算后的准确率与速度、单位、通过状态、完成时间和结果指纹。最终作答只用于结算校验，不另外保留逐次按键日志。

课程和文章定义由本地数据文件提供，练习目标在创建会话时快照化，避免内容更新影响已发起练习。时间戳由后端以 UTC 保存，在界面转为本地时间显示。

关卡进度从已保存且通过的成绩推导：第一关默认开放，其余关卡要求全部前置关卡已有通过记录。复习失败不会删除此前通过记录，因此不会回锁。无需单独维护容易失配的解锁表；成绩事务提交后，新进度自然生效。

结果保存使用数据库事务和唯一会话键。同一会话的相同指纹返回既有成绩，不重复插入；不同指纹返回冲突。写入失败时回滚，不产生通过状态，前端保留冻结结果并允许以同一会话重试。成功响应携带服务端计算的最新进度，前端收到后才显示下一关已开放。

数据库位于 Flask 实例目录，常规启动仅创建缺失的表，绝不执行删除旧表、清空成绩或覆盖数据库的初始化。把数据库排除出版本控制，并在说明中标出数据位置和手动备份方法。

## Risks / Trade-offs

- [中文输入事件顺序存在浏览器差异] → 使用已提交快照和明确的组字状态，验证一次提交仅计分一次；在 Windows 的 Edge/Chrome 中进行真实输入法验收。
- [短素材导致限时提前结束，或后台计时漂移] → 限时循环素材，用截止时刻检查输入，不依赖计时器回调次数。
- [显示百分比舍入造成误通关] → 服务端以整数计数比较 95% 门槛，客户端展示与通关提示分开。
- [保存失败或重复请求造成成绩、解锁不一致] → 唯一会话键、事务保存、基于成功成绩派生进度及冻结结果重试。
- [课程变更影响既有进度] → 为关卡使用稳定标识和课程版本；初版固定课程顺序，后续改版另行设计迁移。
- [单一数据库会被本机所有访问者共用] → 这是个人练习模型的一部分，常规启动绑定 `127.0.0.1`，不把该版本配置为多人服务。

## Migration Plan

这是从零建立应用，没有既有业务数据迁移。实施时先建立应用和版本化内容，再添加非破坏性的数据库初始化和启动说明。首次启动只创建缺失的数据库及表；第二次启动须验证成绩与关卡状态仍在。

应用回退时保留实例目录及数据库，不以删除数据作为回退步骤。后续如需更改已使用的表结构，应先备份并另行提供版本迁移，不能重用清空式初始化。
